# EM Lumen · מערכת שילוט דיגיטלי למסך הכניסה של איתן מדיקל

מערכת מלאה להצגת שקופיות, תמונות, סרטונים והודעות על מסך הכניסה, עם ממשק ניהול מרחוק.

המערכת רצה בשתי סביבות מאותו קוד, ובוחרת את הסביבה אוטומטית:
- **Vercel** (ענן): Postgres של Neon ו-Vercel Blob. ההוראות בסעיף [פריסה ל-Vercel](#פריסה-ל-vercel).
- **שרת מקומי** (Windows או Docker): SQLite ותיקייה בשרת. ההוראות בסעיף [התקנה (Windows Server)](#התקנה-windows-server).

| ממשק | כתובת | למי |
|---|---|---|
| **תצוגה (נגן)** | `https://<הכתובת הקבועה>/player/<מפתח-מסך>` | הדפדפן שעל מסך הכניסה, במצב קיוסק |
| **ניהול** | `https://<הכתובת הקבועה>/admin/` | עובדים מורשים, כניסה ב-SSO של Microsoft 365 |

## מה יש במערכת

**תצוגה שלא נופלת**
- הנגן עובד **גם בלי רשת**: כל התוכן והמדיה נשמרים בדפדפן של המסך (Service Worker ו-Cache). כשהרשת חוזרת הוא מתעדכן לבד.
- תוכן חדש מתחיל להופיע רק אחרי שכל הקבצים שלו ירדו למסך, כך שלא מוצגת שקופית חסרה.
- עדכון מיידי (Server-Sent Events) וגם בדיקה תקופתית כגיבוי.
- שכבות התאוששות: זיהוי לולאה תקועה, הגנה מסערת שגיאות, הגנת זיכרון ורענון יומי מתוזמן. בצד המחשב, סקריפט קיוסק מפעיל מחדש את הדפדפן אם נסגר או נתקע, והשרת רץ כשירות שעולה מחדש אוטומטית.
- תיקון סטייה בשעון המסך לפי שעון השרת, ושמירה על המסך דלוק (Wake Lock).

**תוכן ועריכה**
- עורך שקופיות ויזואלי: טקסט, תמונה, לוגו, וידאו, צורות, שעון, תאריך (גם תאריך עברי), ספירה לאחור וטקסט רץ.
- גרירה, שינוי גודל, הצמדה לקווי עזר, שכבות, נעילה והסתרה, ביטול וביצוע מחדש, העתקה והדבקה בין שקופיות, ושמירה אוטומטית.
- 13 סוגי מעברים בין שקופיות (עמעום, החלקה, זום, טשטוש, ניגוב, היפוך, קובייה ועוד) ו-9 אנימציות כניסה לרכיבים.
- משך שקופית: **15 שניות כברירת מחדל**, ניתן לשינוי בכל שקופית. אפשר גם לקבוע משך לפי אורך הסרטון.
- 8 תבניות מוכנות: כותרת ולוגו, תמונה עם כיתוב, וידאו מסך מלא, הודעה לעובדים, ברוכים הבאים לאורחים, יום הזיכרון, ספירה לאחור, ריקה.
- מאגר מדיה עם לשונית **לוגואים** נפרדת, ותמיכה בגופנים מותאמים (קבצי TTF, OTF ו-WOFF של המותג).

**קטגוריות ותזמון**
- "ימים רגילים" היא קטגוריית ברירת המחדל. כל קטגוריה אחרת מוגדרת בשני אופנים: **מחליפה** (למשל יום הזיכרון, שבו מוצגות רק השקופיות שלה) או **מתווספת** (השקופיות שלה מצטרפות לסבב בזמן שהיא פעילה).
- כללי תזמון: ימים ושעות קבועים (כולל טווח שחוצה חצות), טווח תאריכים, תאריך שנתי, תאריכים מסוימים, **חגים ומועדים ישראליים שמחושבים אוטומטית כל שנה** (כולל הכללים להזזת יום הזיכרון, יום העצמאות ויום השואה), והחרגות ("חוץ מ").
- תזמון גם ברמת שקופית בודדת, למשל מבצע עד סוף החודש.
- עדיפויות בין קטגוריות מחליפות.
- לוח זמנים שבועי ויזואלי והדמיה של "מה ירוץ ביום X בשעה Y".

**ניהול**
- SSO מול Microsoft Entra ID, וגם משתמש מנהל מקומי לחירום.
- שלוש הרשאות: צופה, עורך, מנהל. אפשר לנהל אותן גם דרך App Roles ב-Entra.
- **טיוטה ופרסום**: שינויים לא מגיעים למסך עד שלוחצים "פרסום". יש היסטוריית גרסאות ושחזור בלחיצה.
- **הודעת חירום** שמופיעה מיד על כל המסכים בלי פרסום: פס תחתון, טקסט רץ או מסך מלא, בשלוש רמות ועם תפוגה אוטומטית.
- ניהול מסכים מרובים: מצב חי לכל מסך (מחובר, מה מוצג, גרסה, מטמון, שגיאות), רענון מרחוק, וקטגוריות לפי מסך.
- יומן פעילות (Audit) של כל פעולה, גיבוי יומי אוטומטי של מסד הנתונים והורדת גיבוי מהממשק.
- ממשק בעברית ובאנגלית עם החלפה בלחיצה, כולל RTL מלא.

## דרישות

- **Vercel**: מנוי Pro, ‏Neon Postgres ו-Vercel Blob (ראו בהמשך). **או**
- **שרת מקומי**: Windows Server, Windows 10/11 או Linux, עם **Node.js 22.13 ומעלה** (LTS). **אין צורך ב-`npm install`**: התלויות שב-`package.json` משמשות רק בענן.
- **כתובת קבועה עם HTTPS** (למשל `lumen.eitanmedical.com`). HTTPS חובה כדי שהמצב הלא-מקוון יעבוד, כי דפדפנים מאפשרים Service Worker רק ב-HTTPS.
- **מחשב תצוגה** ליד המסך (מיני-PC עם Windows ו-Chrome או Edge מומלץ) או כל מסך עם דפדפן Chromium עדכני.

## פריסה ל-Vercel

**מה רץ איפה ב-Vercel:**

| רכיב | ב-Vercel |
|---|---|
| ממשק הניהול והנגן | קבצים סטטיים ב-CDN של Vercel (תיקיית `public/`) |
| API, ‏SSO והתחברות | פונקציה אחת: `api/index.js` (Node.js, אזור `fra1`) |
| מסד נתונים | Neon Postgres (דרך ה-Marketplace של Vercel) |
| תמונות, סרטונים, לוגואים וגופנים | Vercel Blob, מאגר **Public**. ההעלאה הולכת ישירות מהדפדפן ל-Blob, כך שאין מגבלת 4.5MB |
| ניקוי לילי | Vercel Cron (`/api/cron/housekeeping`) |
| גיבוי | Neon (שחזור לנקודת זמן), ובנוסף ייצוא JSON מעמוד ההגדרות |

**הבדל אחד מהשרת המקומי:** ב-Vercel אין חיבור חי (SSE), ולכן המסך בודק עדכונים כל 20 שניות. פרסום והודעת חירום מגיעים תוך פחות מ-20 שניות. המצב הלא-מקוון של המסך זהה בשתי הסביבות.

### שלבי ההקמה

1. **ייבוא הפרויקט**: ב-Vercel בוחרים **Add New ← Project**, מייבאים את הריפו מ-GitHub ומשאירים את Framework Preset על **Other**. כל ההגדרות כבר נמצאות ב-`vercel.json`.
2. **מסד נתונים**: בפרויקט נכנסים ל-**Storage ← Create ← Neon (Postgres)**, בוחרים אזור **Frankfurt (eu-central-1)** ומחברים לפרויקט. המשתנה `DATABASE_URL` נוסף אוטומטית.
3. **אחסון מדיה**: ב-**Storage ← Create ← Blob** בוחרים **Public** ואזור **Frankfurt**. בחיבור לפרויקט מסמנים **Add a read-write token env var**, כי בלעדיו אי אפשר להעלות קבצים מהדפדפן.
4. **משתני סביבה** (Settings ← Environment Variables, סביבת Production):
   - `SESSION_SECRET`: מחרוזת אקראית ארוכה
   - `CRON_SECRET`: מחרוזת אקראית ארוכה
   - `BASE_URL`: הכתובת הקבועה, למשל `https://lumen.eitanmedical.com`
   - `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `ALLOWED_EMAIL_DOMAINS`, `ADMIN_EMAILS`: ראו [הגדרת SSO](#הגדרת-sso-ב-microsoft-entra-id)
   - `LOCAL_ADMIN_PASSWORD`: לא חובה, להתקנה ראשונה ולחירום
5. **דומיין קבוע**: ב-**Settings ← Domains** מוסיפים את הכתובת ומגדירים ב-DNS את רשומת ה-CNAME ש-Vercel מציג. תעודת HTTPS נוצרת אוטומטית.
6. **Redirect URI ב-Entra**: `https://<הכתובת הקבועה>/auth/callback`
7. **פריסה מחדש** (Deployments ← Redeploy), כדי שכל המשתנים ייכנסו לתוקף. אחר כך פותחים את `https://<הכתובת>/healthz`. התשובה התקינה היא `"ok":true,"db":"postgres","media":"blob"`.

### חשוב לדעת
- **הגנת פריסות (Deployment Protection)**: אסור להפעיל הגנה על דומיין ה-Production, אחרת מסך הכניסה לא יוכל לטעון את הנגן. ההגדרה הרגילה של Vercel, שמגינה רק על Preview, תקינה.
- **Preview deployments** מתחברים לאותו מסד נתונים אם הוא מחובר גם לסביבת Preview. מומלץ לחבר את Neon ואת Blob ל-**Production בלבד**, או להשתמש ב-branch נפרד של Neon ל-Preview.
- **עלויות**: מסך אחד שולח בערך 4,000 בקשות קטנות ביום (בדיקות עדכון ודיווחי מצב). זה זניח במנוי Pro. המדיה נשמרת במסך, ולכן תעבורת Blob משמעותית רק בהעלאה ובסנכרון הראשון.
- **עדכון גרסה**: `git push` לענף הראשי, ו-Vercel פורס אוטומטית. מיגרציות של מסד הנתונים רצות לבד.

## התקנה (Windows Server)

1. **התקנת Node.js** 22 LTS מ-<https://nodejs.org>.
2. **העתקת התיקייה** לשרת, למשל `C:\EM-Lumen`.
3. **הגדרות**: מעתיקים את `.env.example` ל-`.env` וממלאים לפחות את השדות הבאים:
   - `BASE_URL`: הכתובת הקבועה, למשל `https://lumen.eitanmedical.com`
   - `SESSION_SECRET`: מחרוזת אקראית ארוכה. אפשר ליצור אותה עם:
     `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
   - פרטי ה-SSO (בסעיף הבא)
   - `LOCAL_ADMIN_PASSWORD`: סיסמה חזקה למנהל מקומי, להתקנה ראשונה ולחירום. אפשר לרוקן אחר כך.
4. **בדיקה ראשונה**: מריצים `npm start` בתיקייה ופותחים `http://localhost:8080/admin/`.
5. **התקנה כשירות**:
   `powershell -ExecutionPolicy Bypass -File deploy\windows\install-service.ps1`
   הסקריפט משתמש ב-NSSM אם הוא קיים (מומלץ: מניחים את `nssm.exe` בתיקייה `deploy\windows`), ואם לא, יוצר משימה מתוזמנת עם הפעלה מחדש אוטומטית.
6. **Reverse proxy ו-HTTPS** לכתובת הקבועה. יש קבצים מוכנים ב-`deploy/`:
   - IIS: `deploy/windows/web.config` (דורש URL Rewrite ו-ARR)
   - Caddy (תעודה אוטומטית): `deploy/Caddyfile`
   - nginx: `deploy/nginx.conf`
7. **DNS**: רשומה פנימית או חיצונית לכתובת הקבועה שמפנה לשרת.

> **חלופה: Docker.** בתיקיית הפרויקט מריצים `docker compose -f deploy/docker-compose.yml up -d --build`. הנתונים נשמרים ב-`deploy/data`.

## הגדרת SSO ב-Microsoft Entra ID

1. ב-Entra admin center: **App registrations ← New registration**
   - שם: `EM Lumen`
   - Supported account types: **Single tenant**
   - Redirect URI (Web): `https://<הכתובת הקבועה>/auth/callback`
2. **Certificates & secrets ← New client secret**. מעתיקים את הערך ל-`OIDC_CLIENT_SECRET`.
3. מעדכנים את `.env`:
   ```
   OIDC_ISSUER=https://login.microsoftonline.com/<TENANT_ID>/v2.0
   OIDC_CLIENT_ID=<Application (client) ID>
   OIDC_CLIENT_SECRET=<הסוד>
   ALLOWED_EMAIL_DOMAINS=eitanmedical.com
   ADMIN_EMAILS=eitan.magen@eitanmedical.com
   ```
4. (מומלץ) **Token configuration ← Add optional claim ← ID ← email**.
5. (לא חובה) **App roles**: יוצרים את `Lumen.Admin`, `Lumen.Editor` ו-`Lumen.Viewer` ומשייכים משתמשים או קבוצות ב-Enterprise applications. התפקידים האלה גוברים על ההגדרה בממשק.
6. (לא חובה) ב-Enterprise applications ← Properties: **Assignment required = Yes**, כדי שרק מי שמשויך יוכל להיכנס.

משתמש חדש שנכנס בפעם הראשונה מקבל את ההרשאה שמוגדרת ב-`NEW_USER_ROLE` (ברירת מחדל: צופה). אפשר גם להוסיף משתמשים מראש בעמוד "משתמשים".

## הפעלת מסך הכניסה (קיוסק)

1. בממשק הניהול, בעמוד **מסכים**, מעתיקים את כתובת המסך. כל מסך מקבל מפתח ייחודי.
2. במחשב התצוגה מעתיקים את התיקייה `kiosk` ומדביקים את הכתובת בשורה `$PlayerUrl` בקובץ `kiosk.ps1`.
3. מריצים פעם אחת כמנהל:
   `powershell -ExecutionPolicy Bypass -File kiosk\install-kiosk.ps1 -NightlyReboot "04:45"`
   הסקריפט מגדיר הפעלה אוטומטית בכניסה למשתמש, מבטל שינה ושומר מסך, ומתזמן אתחול לילי (לא חובה).
4. מגדירים כניסה אוטומטית למשתמש הקיוסק (`netplwiz` או Autologon), וב-BIOS מגדירים **Restore on AC power loss = On**.

מה הסקריפט עושה: פותח את Chrome (או Edge) במסך מלא עם פרופיל ייעודי, מפעיל מחדש אם הדפדפן נסגר, ומפעיל מחדש אם הדף הפסיק לשלוח סימני חיים בזמן שהשרת זמין (למשל "Aw, Snap" או דף תקוע).

**על המסך עצמו**: לחיצה על `i` מציגה מידע אבחון (גרסה, חיבור, מטמון, שגיאות). `Ctrl+Shift+R` מרענן.

ל-Linux או Raspberry Pi יש את `kiosk/linux-kiosk.sh`.

## שימוש יומיומי

1. **מאגר מדיה ולוגואים**: מעלים תמונות, סרטונים (מומלץ MP4 בקידוד H.264 ו-1080p) ואת הלוגואים של החברה ללשונית "לוגואים".
2. **קטגוריות ושקופיות**: בקטגוריה "ימים רגילים" לוחצים "שקופית חדשה", בוחרים תבנית ועורכים. העריכה נשמרת אוטומטית.
3. **פרסום**: כשמוכנים, לוחצים **"פרסום למסכים"** בסרגל העליון. המסכים מתעדכנים תוך שניות.
4. **מועדים**: הקטגוריות "יום הזיכרון", "יום השואה" ו"יום העצמאות" כבר מוגדרות לפי לוח השנה העברי (מהערב שלפני). צריך רק להוסיף להן שקופיות ולפרסם.
5. **אירוע חד-פעמי**: יוצרים קטגוריה חדשה מסוג "מחליפה" או "מתווספת" עם כלל "טווח תאריכים".
6. **לוח זמנים**: בודקים מה ירוץ בכל יום ושעה ומריצים הדמיה.
7. **הודעת חירום**: מקלידים טקסט ולוחצים "הפעלה עכשיו". ההודעה מופיעה מיד על כל המסכים.

## גיבוי, עדכון ושחזור

- **ב-Vercel**: Neon שומר היסטוריה לשחזור לנקודת זמן, והקבצים נשמרים ב-Blob. בעמוד ההגדרות יש גם "הורדת ייצוא נתונים (JSON)".
- **בשרת מקומי: גיבוי אוטומטי** של מסד הנתונים כל לילה בשעה 03:00 אל `data/backups` (נשמרים 30 גיבויים, ניתן לשינוי). בנוסף אפשר להוריד גיבוי ידני מעמוד ההגדרות.
- **מה לגבות**: את כל התיקייה `data` (מסד הנתונים והמדיה) ואת `.env`.
- **שחזור**: עוצרים את השירות, מעתיקים קובץ גיבוי ל-`data/lumen.db` (ומוחקים את `lumen.db-wal` ו-`lumen.db-shm` אם קיימים) ומפעילים את השירות מחדש.
- **עדכון גרסה**: עוצרים את השירות, מחליפים את התיקיות `server`, `shared`, `public`, `kiosk` ו-`deploy` ואת הקובץ `package.json` (בלי לגעת ב-`data` וב-`.env`), ומפעילים מחדש. מיגרציות של מסד הנתונים רצות אוטומטית.
- **בדיקה עצמית** של מנוע התזמון ולוח החגים: `npm run check`.

| המסך לא מתעדכן מיד אחרי פרסום | ה-reverse proxy מחזיק תשובות בבאפר. ב-IIS או ARR מגדירים Response buffer threshold = 0 (ראו `web.config`). בינתיים העדכון מגיע תוך דקה דרך הבדיקה התקופתית. |
| הכניסה ב-SSO נכשלת | בודקים שה-Redirect URI זהה בדיוק ל-`BASE_URL/auth/callback`, ובודקים את `OIDC_ISSUER` ואת הסוד. פרטי השגיאה נכתבים ל-`data/logs`. |
| וידאו לא מתנגן | קידוד H.264 ב-MP4 נתמך בכל מקום. HEVC (H.265) לא נתמך בכל הדפדפנים. |
| אין קול בסרטון | מפעילים "לאפשר קול" בהגדרות. הדפדפן חייב לרוץ עם `--autoplay-policy=no-user-gesture-required`, וזה כלול בסקריפט הקיוסק. |
| Vercel: העלאת קובץ נכשלת | חסר `BLOB_READ_WRITE_TOKEN`: בחיבור ה-Blob לפרויקט צריך לסמן "Add a read-write token env var", ואז לבצע Redeploy. המאגר חייב להיות Public. |
| Vercel: ‏`/healthz` מחזיר 503 | מסד הנתונים לא מחובר (`DATABASE_URL`). את הפרטים רואים ב-Vercel ← Logs. |
| גופן לא מוצג במסך | גופני מערכת חייבים להיות מותקנים במחשב התצוגה. גופן שהועלה למאגר עובד תמיד. |

לוגים של השרת נכתבים ל-`data/logs/server-YYYY-MM-DD.log`. בדיקת חיים: `GET /healthz`.

## אבטחה ופרטיות

- הכניסה לממשק עוברת רק דרך SSO, או דרך מנהל מקומי אם הוגדר. העוגיות מוגדרות `HttpOnly`, `SameSite=Lax` ו-`Secure` כשהכתובת ב-HTTPS. יש הגנת CSRF, מדיניות CSP והגבלת ניסיונות כניסה.
- הנגן ניגש לתוכן עם מפתח מסך אקראי. אפשר להחליף מפתח בכל רגע מעמוד המסכים.
- קבצי SVG מוגשים בארגז חול (CSP sandbox).
- **אין להעלות למערכת מידע אישי של מטופלים או מידע רפואי מזהה.** התוכן מוצג במרחב ציבורי. בכל שאלה בנושא פרטיות פונים לממונה הגנת הפרטיות (DPO).
- כל פעולה נרשמת ביומן הפעילות.

server/      שרת Node: ‏API, ‏SSO, מסד נתונים (SQLite או Postgres), מדיה (תיקייה או Blob), פרסום, חגים
api/         נקודת הכניסה של פונקציית Vercel
scripts/     שלב ה-build ב-Vercel (בניית ספריית ההעלאה ל-Blob ובדיקת משתנים)

public/player/  הנגן (תצוגה) ו-Service Worker למצב לא מקוון
public/admin/   ממשק הניהול (עברית ואנגלית)

data/        נוצר אוטומטית: מסד נתונים, מדיה, גיבויים, לוגים (לא נכנס ל-git)
